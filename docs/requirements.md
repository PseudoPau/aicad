状态：**v0.2（2026-11-19），已分拣**。现状一栏核对的是基线提交 `a274779`。

本文件是需求的唯一出处。流程、原型和 README 只引用这里的编号，不再各写一套。用户流程见 [flow.md](flow.md)，关键取舍见 [decisions.md](decisions.md)，此前的计划见 [history/PLAN-2026-11-19.md](history/PLAN-2026-11-19.md)。

## 1. 定位

> 方案人员拿到现场照片和一款标准货架，按场地和需要改成非标方案后，能立刻知道哪些件还是标准件、哪些变成了非标件，各多少件、对应什么 SKU、造价多少，并把同一份方案交给报价和 CAD 人员。

- **用户**：货架方案人员。
- **任务**：把标准款改成非标方案，并把件数、SKU 和造价算清楚。
- **交付去向**：报价拿到清单和造价；CAD 人员拿到参数、清单和带尺寸的二维图。
- **视觉 AI 的角色**：从照片估计场地大小，识别已有货架的型号。结果是估计，由人确认，不要求高精度。
- **不使用 CadQuery**：预览由浏览器用布局数据直接绘制，不导出 STEP。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 标准款 | 一款有固定默认尺寸和构件规格的标准货架，是方案的起点 |
| 标准件 | 形式和尺寸都在标准件目录里的构件，有 SKU 和目录价 |
| 尺寸非标件 | 形式与标准件相同，但尺寸不在规格表内，需要定制下料。例如横梁长度不在标准系列里 |
| 形式非标件 | 构件形式与标准件不同。本轮只包含连接方式的改变；截面和孔型放到后续 |
| 排列方式 | 货架在场地里怎么排，例如单排、背靠背双排 |
| 清单 | 一份方案的全部构件：类别、规格、标准或非标、SKU、件数、单价、小计 |
| 造价 | 标准件按目录价；非标件按系数估算并注明需要询价 |

## 4. 本轮验收

1. 从标准款开始，不改任何参数：清单全部是标准件，都有 SKU，造价等于目录价之和。
2. 把每跨宽度改成规格表里没有的值：横梁和层板变成尺寸非标并说明原因，立柱不变；这些件的价格是系数估算，标有“需询价”。
3. 改变连接方式：受影响的构件变成形式非标。
4. 从单排改成背靠背：件数相应变化，连接杆计入清单。
5. 清单包含紧固件、连接件和护栏，并写明件数规则。
6. 修改参数后，清单、预览和二维图一起更新；导出的清单、二维图和参数 JSON 版本标识一致。
7. 清单件数与布局计算的件数一致，由自动化测试保证。
8. 视觉估计的场地尺寸和型号在确认之前不进入方案；没有视觉服务时，手工填写也能走完全流程。
9. 全流程不需要安装 CadQuery。

## 5. 现状问题

- **双排连接杆没有建模**：`spacer_length` 只影响排间距，连接杆件数记为 0。
- **紧固件和护栏没有计入**：Schema 里有 `guard_rail` 类型，但没有对应实现。
- **预览和导出都绑在 CadQuery 上**：`core/translator.py`、`core/components.py` 和 `ui_server.py` 的生成路径需要替换。
- **视觉代码的用途不对**：`core/vision_agent.py` 的提示词要求提取全部几何参数，需要改成只估计场地大小和型号。
- **斜撑留空值有两处定义**：`core/pipeline.py` 里是 50，`core/geometry_contract.py` 里是 100，含义不同，需要统一成一处。

斜撑只生成在两端的立柱片，这是已确认的件数规则，不是缺陷。

## 6. 待定问题

前四项由调研回答，后三项需要你决定。

1. **调研的市场范围**：我默认以中国大陆市场、人民币计价为准。
2. **标准款和规格**：有哪些常见的标准款，各自的长度系列、高度和截面规格是什么。
3. **连接方式和排列方式的选项**：行业里有哪些常见做法，本轮各放哪几种。
4. **用量规则和估算系数**：每处连接用多少紧固件，护栏怎么配；非标件的估算系数取多少。查不到依据的值会标为示例。
5. **排列方式是否影响单个构件的属性**：我的理解是它只改变件数和连接件，不会让某个构件变成非标件。
6. **二维图的格式**：我建议导出 DXF，CAD 人员可以继续编辑；页面上另有一份可直接看的图。
7. **视觉服务**：现有代码用的是智谱 GLM-4V，需要 API 密钥。是否沿用，以及由谁提供密钥。
