## 四项硬验收

这次重处理不以“代码存在”作为完成标准，而以四个可审阅结果收口：

1. **链路跑通**：在明确的本地环境中，从示例/输入参数完成校验、构造、检查和导出；缺少真实模型时也能用离线 fixture 完成确定性链路。
2. **构造正确**：关键尺寸、构件数量、位置关系、层高、单双排和斜撑规则有可执行断言；非法或不完整参数会阻塞构造。
3. **有可用体验**：用户能在本地 UI 中加载示例、确认参数来源、修改参数、看到预览/检查状态并导出结果；失败时保留草稿和下一步。
4. **证明拓展性**：视觉输入、参数协议、几何构造、校验、UI 状态和导出之间有稳定边界；至少用第二个货架变体或第二组 fixture 证明新增规则不需要复制整条链路。

四项验收分别对应 E1 固定夹具、几何断言、一次可完成任务的交互记录和第二变体的架构证据。真实模型调用与目标用户验证仍单独记为 E2/E3。

## 结论先行

aicad 值得作为一个窄任务继续验证，但暂时不应定位成“通用图生 CAD”或生产级结构设计器。

最有价值的独立假设是：货架方案设计或现场测绘人员，给出一到两张现场照片和少量已知尺寸后，得到一份可校正、可检查、可导出的标准货架几何草案，用于复核、报价或与 CAD/加工人员交接。

这个任务和 CreateJunior 的用户、输入纪律、输出目的不同，因此可以独立成立。当前没有真实用户、效率、精度或 STEP 可用性证据；继续投入的理由是验证这条任务链，而不是沿用旧的“CreateJunior 前期探索案例”判断。

首轮要证明的不是视觉模型有多强，而是：不确定性是否被看见、关键尺寸是否能被确认、几何是否稳定、用户能否在一次任务中完成校正到导出。

## 当前真实能力与断点

已实现的代码能力：

- main.py 固定读取 tests/rack_photo.jpg、tests/shelf_instance.json、schema/assembly_schema.json。
- core/vision_agent.py 将图片转 base64，调用 glm-4v，把 Schema 和样例嵌入 prompt，并用正则截取 JSON。
- core/validator.py 调用 jsonschema.validate。
- core/translator.py 生成货架立柱、横梁、层板、底板和边界斜撑，并由 main.py 调用 CadQuery 导出 STEP。
- Schema 约束了若干字段类型，样例覆盖单组宽高深、跨数、双排和三类组件。

影响复现和产品可信度的断点：

- README 要求 .env 中填写 AI_API_KEY，代码读取 ZHIPU_API_KEY。
- 输入图片和模板路径写死，没有上传、命令行参数或项目级输入记录。
- OUTPUT_DIR 指向 BASE_DIR.parent/output，README 的目录说明却写成仓库根目录 output/；本次克隆目录内已有 STEP 不能证明入口可重跑。
- setup_env.ps1 只安装 Conda/CadQuery/ocp-vscode，没有安装代码实际需要的 zhipuai、jsonschema、python-dotenv；requirements.txt 是带大量 file:///home/...、D:/bld/...、C:/... 构建路径的环境导出。
- 视觉输出没有尺寸来源、置信度、缺失字段或人工确认状态；没有 JSON response format、重试和结构化错误恢复。
- Schema 没有完整的正数/范围约束、组件集合约束或类型与参数分支绑定；guard_rail 枚举存在，但没有对应参数分支。
- 翻译器将层板厚度、底部起步、顶部留白、斜撑目标间距和部分间隙写死；spacer_length 只参与双排排布，未实际生成连接杆；底板是无孔矩形拉伸。
- test_translator.py 读取预先存在的 output/extracted_instance.json，没有断言，缺文件时只打印后返回。
- 所有 Python 文件可做 AST 解析；当前环境无法导入 CadQuery，因此几何、碰撞和 STEP 有效性仍未验证。

README 中关于 Spacer Bars、连接件、底板螺栓孔、LOD350 细节、倒角和“可直接用于工业生产”的描述，当前不能从实现得到支持，应在产品文案和展示中暂时删除或改为待验证事项。

## 首要用户与任务假设

目标用户是货架方案设计人员、现场测绘人员或小型集成商。先只验证一个场景：

1. 用户上传一到两张货架现场照片，选择单位并填写项目名称。
2. 系统识别单排/双排、跨数、层数和可见构件，显示每个值的来源。
3. 用户确认或修正总宽、深、高、跨数、层数及关键型材尺寸。
4. 系统生成可旋转的货架三维草案。
5. 用户改一处尺寸或结构，预览同步变化，可撤销。
6. 系统执行几何和输入检查，导出 STEP、JSON 参数和一份尺寸/假设报告。

这是待验证假设。尚无证据证明谁会实际使用、任务频率、可接受误差、现有替代流程耗时、照片能否提供隐藏尺寸，以及用户是否信任导出的 STEP。必须输入或确认：单位、单排/双排、总宽/深/高或基准尺寸、跨数、层数、立柱/横梁/斜撑规格、双排间距和连接方式、照片方向与尺度参照。照片推断、用户输入和默认值必须分层展示，默认值不能伪装成测量值。

## 最小产品流程与界面结构

1. **上传 / 示例**：上传照片，或先用固定示例进入流程；显示单位和项目名称。
2. **识别草稿**：展示识别出的结构树和三维草图，不直接宣称“已测量”。
3. **参数来源与校正**：逐项显示值、来源（照片/用户/默认）、置信度、是否必填；缺关键尺寸时阻塞继续。
4. **三维预览**：单排/双排、跨数、层数可视化；标出未知、冲突和采用的默认值。
5. **修改反馈**：表单和简短自然语言都可改参数；显示变化前后，支持撤销和回到上一个有效版本。
6. **检查**：检查负值、零值、层间距、悬空、缺组件、尺寸冲突和导出前置条件；阻塞项必须可定位。
7. **导出**：同时导出 STEP、最终 JSON、检查结果和来源/假设报告；未检查的项明确标注。

界面先做一条闭环，不做通用 CAD、自由曲面建模或“万能图生三维”。

## 可独立关闭和重开的 AI 工作包

### A. 可运行性基线

- 输入：仓库、当前 Python/Conda 环境、固定样例 JSON/图片。
- 动作：清理依赖清单；统一环境变量；把图片、JSON、输出目录改为参数；提供无模型的 fixture→validate→STEP 命令；记录版本和产物位置。
- 验收：干净环境可运行一条命令；样例验证有断言；若装有 CadQuery，固定 fixture 能生成 STEP，并检查文件存在和大小。
- 暂停点：CadQuery 安装、平台兼容性或模型密钥无法解决时暂停，不用伪造通过。
- 可自主完成：依赖和入口修正、无模型测试、错误信息、运行记录。需要外部判断：CadQuery 版本选择和真实部署环境。

### B. 确定性几何与校验

- 输入：样例 Schema、components.py、translator.py、已确认的货架规格资料。
- 动作：把硬编码尺寸变成显式参数；补正数、范围、组件集合和类型绑定；对缺组件、层数不足、尺寸冲突给出可读错误；增加固定夹具和几何性质检查。
- 验收：相同输入生成稳定 STEP；非法参数被拒；关键构件数量、位置、间距和版本可检查。
- 暂停点：缺少真实型材和连接规则时暂停，不自行发明生产规格。
- 可自主完成：Schema、纯函数、固定夹具和错误路径。需要用户/专家判断：默认值、规格边界、何种碰撞或间距可接受。

### C. 最小交互闭环

- 输入：A/B 的稳定接口、示例照片、参数来源模型。
- 动作：实现上传/示例→校正→预览→修改→检查→导出的最小 UI 或 CLI。
- 验收：新用户能完成一条示例任务；每个阻塞项可定位；修改后预览和导出使用同一版本。
- 暂停点：信息架构、字段顺序和默认值需要真实用户判断时暂停。

### D. 错误恢复

- 输入：视觉返回、Schema、几何和导出错误样本。
- 动作：覆盖缺图、模糊照片、非法 JSON、缺字段、几何失败、导出失败；保留可编辑草稿和重试入口。
- 验收：每类故障都有可理解提示，用户不会丢失已确认参数。
- 暂停点：依赖模型服务的错误格式和重试语义。

### E. 示例与文档

- 输入：两到三个代表性照片/参数夹具、运行基线。
- 动作：写清输入规范、单位、来源标签、限制和输出；准备一个单排和一个双排示例。
- 验收：新用户能按 README 完成示例；展示产物、检查结果和假设报告。
- 暂停点：缺少可公开使用的真实照片或尺寸资料时，用合成/授权夹具并明确标注。

### F. 展示与价值证据

- 输入：C/D/E 的一次完整任务记录。
- 动作：录制上传、参数确认、校正、预览、检查和导出的完整过程；记录人工基线、修改点、失败和用户反馈。
- 验收：能具体说明一次任务节省了哪一步，并展示输入、来源、变化前后和最终产物。
- 暂停点：必须有至少一名目标用户或熟悉货架/CAD 的使用者参与。

### 首轮执行顺序

**A → B → E → C → D → F**。

建议首轮只开 A1 可运行性基线 + B1 确定性夹具：先把依赖、入口、输入/输出和无模型验证固定下来，再用一个单排和一个双排 fixture 把 Schema、组件数量、层高分配和 STEP 生成变成可检查结果。在 A1/B1 通过前，不接真实模型、不做全量重写、不做泛化功能。

## 暂停、恢复与决策门

暂停时保存当前提交、环境版本、命令和失败日志；已确认参数与来源；未解决的规格问题；下一包的输入和验收命令。

恢复时从本文件对应工作包开始，重新读取仓库原生 README 和代码，不把本索引当作代码事实。

当 A/B/E 已通过且至少一名目标使用者完成一次 20–30 分钟任务后，再决定是否继续 C/D/F 的完整实现。任务记录至少包含：哪些字段被改、何处不信任、是否能解释导出结果、与人工基线相比节省了哪一步。一次成功不能外推成稳定能力。

若无法取得真实尺寸资料，或用户不愿让照片推断结果进入校正流程，应收缩为“参数化货架草案生成器”，保留视觉输入作为可选加速入口。
